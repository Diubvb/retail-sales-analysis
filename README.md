零售销售数据分析项目



一、项目简介

本项目基于模拟零售销售数据集，使用 MySQL 和 Power BI 完成数据质量检查、SQL 数据分析、数据建模及交互式可视化，旨在分析不同商品品类、销售地区及月份的经营表现。

项目类型： 个人数据分析练习项目

数据性质： 模拟数据，非真实企业经营数据

数据时间范围： 2023年全年

数据规模： 1,825 条销售记录

使用工具： MySQL Power BI、DAX



二、数据说明

数据包含以下字段：

Date（销售记录日期）

Category（商品品类）

Sales（销售额）

Quantity（销售数量）

Profit（利润）

Region（销售地区）



该数据集用于模拟零售经营场景，支持从品类、地区和月份等维度观察销售表现。



三、分析工作



1\. 数据质量检查：检查数据总量及字段缺失情况。检查字段数据类型。识别需要进一步核实的异常记录。



2\. SQL 数据分析：使用 MySQL 完成：整体经营指标统计。不同商品品类的销售额、利润、销量及利润率分析。不同地区的经营表现对比。品类与地区交叉分析。月度销售趋势及利润率分析。使用 LAG 窗口函数计算月度销售额环比增长率。使用窗口函数计算累计销售额。



3\. Power BI 可视化：建立数据模型并使用 DAX 创建经营指标，制作四个报表页面：经营概览、品类与地区分析、月度趋势分析、数据说明与分析口径、报表支持跨页面筛选及页面导航。

五、数据限制与分析口径



数据为模拟数据，分析结论不代表真实企业经营状况。

数据仅覆盖2023年，无法据此判断多年季节性变化。

数据集中存在部分 Category、Sales、Quantity 和 Region 缺失记录。

部分销售数量为0但销售额及利润为正的记录保留待核实。

按品类或地区分组的统计排除了对应维度为空的记录，因此分类统计结果与包含全部记录的整体指标存在差异。

数据集文档将 Profit 描述为净利润，但未提供具体成本构成与核算过程，本项目仅按照 Profit 字段进行统计，不进一步推断其具体财务核算口径。

数据不包含订单ID，因此使用销售记录数，不将记录数解释为订单数。
